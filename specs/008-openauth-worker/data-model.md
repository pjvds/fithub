# Data Model: feat-008-openauth-worker

## Existing Entities (no migrations required)

### `users` (D1 — `FithubDb`)

| Column         | Type           | Constraints         | Notes                          |
|----------------|----------------|---------------------|--------------------------------|
| `id`           | `text`         | PRIMARY KEY         | UUID generated at account creation |
| `email`        | `text`         | NOT NULL, UNIQUE    | Identity key; used by `success` callback |
| `display_name` | `text`         | nullable            | Not set at creation; future profile feature |
| `created_at`   | `timestamp_ms` | NOT NULL, DEFAULT   | First sign-in timestamp        |
| `updated_at`   | `timestamp_ms` | NOT NULL, DEFAULT   | Last modification timestamp    |

**No schema migration needed.** The `users` table is already defined and deployed.

## Auth State (KV — `AuthKv`)

All entries managed automatically by OpenAuth.js `CloudflareStorage`. No manual reads or writes to this namespace by application code.

| Key Pattern                 | Value         | TTL        | Notes                         |
|-----------------------------|---------------|------------|-------------------------------|
| `openauth:keys:*`           | JWK signing keys | Rotated automatically | Auto-generated by OpenAuth.js |
| `openauth:otp:{code_id}`    | OTP state     | 15 minutes | Single-use enforcement        |
| `openauth:session:{token}`  | Session metadata | 30 days | Refresh token backing store   |

## Token Subject Schema (shared module)

```ts
// packages/functions/src/shared/subjects.ts
import { createSubjects } from "@openauthjs/openauth/subject";
import { object, string } from "valibot";

export const subjects = createSubjects({
  user: object({ id: string() }),
});
```

**Token payload shape** (JWT `properties` field after `client.verify()`):
```ts
{
  type: "user",
  properties: { id: string }  // FitHub internal user UUID
}
```
