# Data Model: 005-web-frontend

> Generated by speckit-plan Phase 1 — view-models, component props, cookie/session schema, and state transitions consumed by the FitHub web app. The web layer owns no database; all entities here are API response shapes, browser state structures, and the session cookie schema.

---

## Storage Overview

| Store | Technology | Purpose |
|---|---|---|
| Session | `HttpOnly` cookie on `fithub.space` | Auth session token (opaque to JS) |
| URL state | Search params / path | Current page, filters, pagination cursors |
| Client cache | `Map` in API client module | In-flight request dedup (no persistent cache) |
| Error queue | JS memory → `POST /api/errors` | Buffered client-side error ingestion |

No `localStorage`, `sessionStorage`, or IndexedDB. All persistent state lives server-side.

---

## Session Cookie Schema

### `fithub_session`

Set by the Auth Worker (`auth.fithub.space`) after a successful OAuth callback.

| Attribute | Value |
|---|---|
| Name | `fithub_session` |
| Domain | `.fithub.space` (apex) |
| Path | `/` |
| HttpOnly | ✅ |
| Secure | ✅ |
| SameSite | `Lax` |
| Expiry | 30 days (rolling) |
| Contents | Signed opaque token (JWT or PASETO); contents verified server-side only |

The cookie is **never read by JavaScript**. Astro server endpoints and the API Worker validate it on the server via the `Authorization: Bearer <token>` header or cookie forwarding.

## API Response View-Models

These are the TypeScript types the web client consumes. Canonical definitions live in `packages/core/src/types/api.ts`; the web app imports them as `@fithub/core`.

### `AuthUser`

Returned by `GET /api/me`. Used by Astro layouts to gate authenticated routes.

```ts
interface AuthUser {
  userId: string;     // UUID
  email?: string;     // nullable (Apple privacy relay)
}
```

### `Connection`

Returned inside `GET /api/connections`. Drives `ConnectionCard` display.

```ts
interface Connection {
  id: string;             // UUID
  platform: 'zwift' | 'strava' | 'apple_health';
  status: 'active' | 'requires_reauth' | 'disconnected';
  connected_at: number;   // epoch seconds
  last_synced_at?: number;
  last_error?: string;
}
```

### `ConnectionsResponse`

```ts
interface ConnectionsResponse {
  connections: Connection[];
}
```

### `SyncJob`

Returned inside `GET /api/sync/history`. Drives `SyncHistoryList`.

```ts
interface SyncJob {
  id: string;
  platform: 'zwift' | 'strava';
  status: 'pending' | 'success' | 'partial' | 'failed';
  started_at: number;     // epoch seconds
  ended_at?: number;
  activities_synced: number;
  error_message?: string;
}
```

### `SyncHistoryResponse`

```ts
interface SyncHistoryResponse {
  jobs: SyncJob[];
  next_cursor?: string;   // null when no more pages
}
```

### `CanonicalActivity`

Returned inside `GET /api/activities`. Drives `ActivityFeed`.

```ts
interface CanonicalActivity {
  id: string;             // UUID
  type: ActivityType;     // see enum below
  started_at: number;
  ended_at: number;
  duration_s: number;
  distance_m?: number;
  calories_kcal?: number;
  avg_heart_rate?: number;
  primary_source: 'zwift' | 'strava' | 'apple_health';
  dedup_group_id?: string; // present when activity is part of a dedup group
}

type ActivityType =
  | 'running'
  | 'cycling'
  | 'swimming'
  | 'hiking'
  | 'walking'
  | 'other';
```

### `ActivitiesResponse`

```ts
interface ActivitiesResponse {
  activities: CanonicalActivity[];
  next_cursor?: string;
}
```

### `ManualSyncResponse`

Returned by `POST /api/sync/trigger`.

```ts
interface ManualSyncResponse {
  job_id: string;
  platform: 'zwift' | 'strava';
  status: 'pending';
  started_at: number;
}
```

### `UserProfile`

Returned by `GET /api/user/profile` (settings page).

```ts
interface UserProfile {
  user_id: string;
  email?: string;
  created_at: number;
  connections: Connection[];
}
```

### `ErrorReport`

Sent by `POST /api/errors`. Browser-to-server error ingest.

```ts
interface ErrorReport {
  code: string;               // ErrorCode enum value
  message: string;
  context?: Record<string, unknown>;
  occurred_at: number;        // epoch ms (client clock)
  correlation_id?: string;    // if available from last server request
}
```

### `ApiError`

Normalised error wrapper returned by `api-client.ts` for any non-2xx response.

```ts
interface ApiError {
  status: number;
  code: string;          // server error code or 'NETWORK_ERROR' / 'TIMEOUT'
  message: string;
}
```

## Client State Models

### `PageState<T>`

Generic wrapper for pages that load async data.

```ts
type PageState<T> =
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: ApiError };
```

For `ActivityFeed` and `SyncHistoryList`.

```ts
interface PaginatedState<T> {
  items: T[];
  next_cursor?: string;
  loading_more: boolean;
  error?: ApiError;
}
```

## State Transitions

### Connection Status

```
active
  └─► requires_reauth    (token refresh failed; user must re-authenticate)
        └─► active        (user completes OAuth flow again)
  └─► disconnected        (user revokes connection in Settings)
disconnected
  └─► active              (user connects platform again)
```

**Web-side handling:**
- `requires_reauth` → show inline re-auth prompt on `ConnectionCard`; block manual sync CTA
- `disconnected` → show "Connect" CTA; grey out sync-related UI

### Sync Job Status

```
pending
  └─► success             (all activities synced)
  └─► partial             (some synced; some errored)
  └─► failed              (all errored or pre-flight failure)
```

**Web-side handling:**
- `pending` → show spinner/progress indicator on dashboard sync badge
- `partial` → show warning badge; link to sync history detail
- `failed` → show error badge; include `error_message` in tooltip

### Manual Sync Lifecycle (client UX)

```
idle
  └─► submitting          (user clicks "Sync Now"; button disabled)
        └─► queued        (202 response; job_id stored)
              └─► polling  (interval check via GET /api/sync/history?job_id=...)
                    └─► done (success / partial / failed) → idle
```
